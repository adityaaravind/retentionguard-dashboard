1 · Order Vault — 90-day retention

Personal fields (name, email, phone, street address) are kept for 90 days, then anonymised. Non-personal facts — order total, SKU count, city-level region — are kept for accounting. Returns and refunds are held in the open, in an exception queue with an expiry, never as a silent loophole.

Exception queue — visible, expiring

Rule: an exception needs a reason, an owner, and a hold-until date. When the hold expires, the record joins the next sweep automatically.

2 · Deletion Proof — tamper-evident certificates

Every sweep creates a batch certificate. Each certificate contains the previous batch's hash, so deleting or editing an old batch breaks the chain — and the Verify button below will catch it. Try it: tamper with a certificate, then verify.

3 · BI Export Guard — least privilege, or it doesn't run

Analysts never touch the raw database. Queries must be parameterized, roles are least-privilege, and any bulk export containing personal data is alerted on and blocked — the pattern behind most “the BI tool did it” breaches.

About this project

RetentionGuard is a reference implementation for third-party data lifecycle management. It demonstrates how a defined retention period can be enforced, evidenced, and audited — rather than relied upon as a policy statement alone.

Scope

  • Retention enforcement — time-bound anonymisation of personal fields after 90 days, with a documented exception process for returns and refunds.
  • Deletion evidence — hash-chained batch certificates that allow deletion events to be verified and tampering to be detected.
  • Access controls — least-privilege, parameterized access to reporting data, with bulk personal-data exports blocked and logged.
  • Vendor oversight — independent verification of third-party deletion attestations against sampled records.
  • Incident scoping — rapid identification of affected records and exposed fields to support accurate notification.

Methodology & limitations

  • All data in this demonstration is synthetic and generated locally in the browser. No real personal data is used.
  • This is a client-side demonstration. A production implementation would require server-side scheduling, immutable (WORM) audit storage, identity-provider integration, and formal data-processing agreements with each vendor.
  • Retention periods should be set with legal and operational requirements for the relevant jurisdiction and data category, not adopted solely from this example.
